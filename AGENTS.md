# FarEastCTF 2026 — вёрстка лендинга

## Задача

Сверстать одностраничный адаптивный лендинг соревнования FarEastCTF 2026 (Хабаровск, 9–10 ноября 2026) **точно по макетам**: desktop 1440 px и mobile 390 px, плюс промежуточные ширины по правилам из `docs/SPEC.md`.

## Стек

- По умолчанию: семантический HTML + современный CSS (custom properties, grid, flex, `clamp()`) + чистый JS. Без фреймворков и UI-библиотек. Для dev-сервера можно взять Vite.
- Весь код — в папке `site/`. Она должна работать сама по себе: нужные файлы из `assets/` и `tokens/` скопируй в неё.
- Если пользователь укажет другой стек (основной сайт fareastctf.ru сделан на Nuxt), делай каждую секцию отдельным компонентом с тем же CSS.

## Материалы

Используй в таком порядке приоритета:

1. `design/screens/` — эталон внешнего вида (PNG @2x).
   - `desktop/01-nav.png` … `09-footer.png` и `mobile/…` — по секциям; длинные секции дополнительно порезаны в `parts/`.
   - `desktop-full.png` (1440) и `mobile-full.png` (390) — страница целиком.
   - `states/mobile-menu-open.png` — открытое мобильное меню; `states/form-states.png` — ошибки и отправка формы.
   - На каждом PNG секции сверху 7 px (14 px @2x) — половинки меток «+» с границы с предыдущей секцией.
2. `design/spec/desktop.json`, `mobile.json`, `mobile-menu-open.json`, `form-states.json` — дерево макета с точными значениями (padding, gap, размеры, шрифты, токены). Компоненты уже развёрнуты, легенда — в начале каждого файла. Имена узлов совпадают с названиями в SPEC.
3. `docs/SPEC.md` — сетка, секции, компоненты, мобильное меню, форма, адаптив, решения по умолчанию, чек-лист приёмки.
4. `docs/CONTENT.md` — все тексты, ссылки и список плейсхолдеров.
5. `tokens/tokens.css` (+ `tokens.json`) — цвета, шрифты, типографика.
6. `design/desktop.html`, `mobile.html`, `mobile-menu-open.html`, `form-states.html` — экспорт pen.dev для визуального сравнения в браузере (картинки — в `design/images/`). Это **не** код для копирования: там абсолютные px и инлайн-стили. Полутонового эффекта «глаза» в нём нет.

## Правила

- Тексты — дословно из `docs/CONTENT.md`, с типографикой: ё, «ёлочки», длинное — и короткое – тире.
- **Плейсхолдеры `[…]` не выдумывать и не удалять.** Выводи их плашкой-плейсхолдером (SPEC 1.4), как в макете. Все тексты, плейсхолдеры и ссылки держи в одном файле контента (например, `site/content.js`), чтобы потом заменить значения в одном месте. Неизвестные URL — `#` с комментарием `TODO`.
- Цвета, шрифты, отступы — только из токенов и макета. Палитру и размеры не «улучшать».
- Брейкпоинт: mobile-макет < 1024 px, desktop-макет ≥ 1024 px (SPEC 1.1). Нигде не должно быть горизонтальной прокрутки.
- Каркас сетки (линии 1px, метки «+», штриховка) — ключевой приём дизайна; линии не должны удваиваться (SPEC 1.2).
- Поведение, которого нет в макете (sticky-шапка, hover, фокус, логика формы), — по SPEC 4–5. Новых секций, анимаций и элементов не добавлять.
- Папки `design/`, `docs/`, `tokens/`, `assets/` — исходники, не изменяй их.

## Проверка

1. Запусти сайт локально, сделай скриншоты на 1440 и 390, сравни с `design/screens/` секция за секцией (отступы, переносы строк, размеры шрифтов, линии, цвета). Расхождения исправь.
2. Проверь ширины 320, 768, 1024, 1280, 1920: нет горизонтальной прокрутки, сетка не ломается.
3. Пройди чек-лист `docs/SPEC.md` § 7: меню, якоря, форма (добавление и удаление участников, валидация, состояния).
